## Task

T-005: make install and uninstall ownership-aware, and register the work-track lifecycle T-004
left unwired.

## Did

- Added `lib/install.js` as the one place that decides what godkit installs and may remove; both
  the standalone installer and the plugin manifest now derive from its `HOOKS` list.
- Registered work-track on PreToolUse, PostToolUse (shell and edit tools) and SessionEnd. This is
  what makes clockout able to fire at all.
- Changed hook filtering from group-level to handler-level — the old code took a user's hook with
  ours whenever they shared a group.
- Gave installed skill directories an ownership rule (link into this package, or a marked copy);
  install refuses a foreign destination and uninstall keeps it.
- Rewrote `scripts/uninstall.js` on the shared library; it now clears the T-004 session-state root
  rather than a flag file that no longer exists, and honours `CLAUDE_CONFIG_DIR`/`CODEX_HOME`.
- Added `scripts/sync-hooks.js` so the plugin manifest is generated, never hand-maintained.

## Decisions

- The plugin manifest became a generated file. It had already drifted once (work-track was missing
  from it), and a generated file cannot drift.
- Package-install ownership does not reuse `evolve.js`'s snapshot hashing. That hash exists to
  detect edits to an APPROVED project skill; for a package install an edited copy is still ours,
  and the folder-style antigravity target does not fit that shape at all.
