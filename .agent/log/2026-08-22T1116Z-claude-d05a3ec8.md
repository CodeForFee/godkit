## Bugs
- found and fixed before it could ship: `bin/godkit.js` `link()` does
  `fs.rmSync(dest, {recursive:true, force:true})` on any directory in the way. Harmless today
  because every destination is `~/.claude/skills/<godkit-skill>`, which godkit created. Pointed at
  `<project>/.claude/skills/<name>` — which is exactly what this feature does — it would have
  **deleted a user's own project skill**. `lib/evolve.js` therefore has its own `ownership()` +
  `linkOne()` and never calls `link()`: it replaces only an absent path, a link resolving back
  into `.agent/skills/`, or a copy carrying a `.godkit-link` marker, and refuses anything else.
  Not filed as `B-NNN` — the latent call path was never reachable before this branch.

## Decisions
- **No new store.** The skills directory and the log stream are the store, per the existing board
  decision that a signature derives from `graph.json` itself. A stale trust record would actively
  mislead an agent into loading a failing skill.
- **Per-skill links, never a folder link.** A folder link would clobber a user's own skills at
  that path and would make phase 2's quarantine unenforceable — a quarantined skill would still
  sit where the host looks.
- **Mode gate is mechanical, at the link step**, not an instruction in a SKILL.md. In
  `audit_only` a generated skill is a committed, inert markdown file no host can load.
- Dropped from the source design and why: SQLite + its 7 tables (`node:sqlite` is 22+, engines
  say 18), embedding/BM25 ranking (the host already ranks on `description` — that *is* the
  retrieval), the behaviour-eval worker and skill sandbox (a skill is instructions, not code),
  the staged-authoring pipeline (git is the audit trail), cloud hub, redaction.
