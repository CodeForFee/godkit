## Decisions
- **Not SQLite**, asked directly by the user. Three reasons, in order of weight: a `.db` is binary
  so git cannot merge it, and the entire protocol rests on per-session files that merge without
  thought — one binary store means every parallel session collides; the logs must stay markdown
  regardless because humans and every tool read them, so a database could only be a derived cache,
  i.e. the second store that desyncs; and `node:sqlite` is Node 22+ while engines say >=18.
  Measured before answering: **500 logs = 235 ms end to end**, of which ~40 ms is node startup,
  180 ms is file I/O and **1 ms** is the O(n²) clustering. It is I/O-bound, so a database does not
  fix what actually costs.
- While measuring I found `candidates()` re-read every log file `readLogSignals()` had already
  read. Tokens are now computed once during the single pass: **candidates 153 ms → 1 ms**,
  end-to-end **390 ms → 235 ms (~40% faster)**, for free and with no new store.
- `.agent/` **stays committed** (user confirmed). `.agent/tmp/` and `.agent/.trash-*` were already
  gitignored, which is what the user had seen greyed out in the file tree.
