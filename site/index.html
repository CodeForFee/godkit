The problem

Every agent arrives blind

It cannot see what was already done, or which files another agent is holding. Private memory cannot fix that: Cursor cannot read Claude's, and Claude cannot read Cursor's.

without godkit

  • Claude Code~/.claude/
  • Cursor.cursor/
  • Codex~/.codex/

Three private memories, none readable by the other two — so the same work gets done twice and two agents edit one file.

with godkit

  • Claude Code
  • Cursor
  • Codex

.agent/ committed — it shows up in the diff

One board, one map, one log, in the repo every tool already opens.

The only shared memory between tools
is the filesystem they both open.

The protocol

Six steps, every session, every tool

Not a suggestion: on Claude Code and Codex a Stop hook blocks the turn until the log exists.

01

Clock in

Read the board, the map, the last two logs.

02

Claim

Your file globs, on the board, before you edit.

03

Work

Inside your scope. Found a bug outside it? File it.

04

Verify

Run the exit condition. A return value is not evidence.

05

Log

Real paths, real commands, real output.

06

Hand off

Release the claim. The next agent starts cold.

and the next session starts at 01 again

Read .agent/ before you edit.

Write your log before you finish.

The shared state

One directory, and it is committed

Not a database, not a service, not a plugin API — markdown every tool can already open and git can already merge.

.agent/
BOARD.md               roster · claims · bugs · decisions — one screen
THREAD.md              append-only conversation between agents
BRIEF.md               what this is, before there is code to map
MAP.md                 what this codebase is (generated)
graph.json             the machine-readable map
sprints/S-001.md       a goal, and the waves of tasks under it
tasks/T-001-*.md       Plan · Execute · Review · Test · Handoff
log/<UTC>-<model>.md   one per session, never edited by anyone else

One log file per session is the whole concurrency design: two tools never write the same file, so git merges them without a thought.

Sprints

Waves that cannot collide

A task is one seam. Several seams aimed at one goal is a sprint — and the only rule that governs a wave is which files it touches.

  1. Wave 1 — runs in parallel T-001T-002T-003

    No two of them touch the same file.

  2. Join gate

    Full suite green before the next wave starts.

  3. Wave 2 — runs in parallel T-004T-005

    A task wanting a file wave 1 claimed waited for this one.

  4. Join gate

    Full suite green again.

  5. Sprint closes every task proven

    sprint close refuses while anything is unproven.

Identity

Signed by a model, never by a tool

rejected agent: "claude" Which model? Costs and failure modes differ.
accepted agent: "claude-opus-5" Answerable — the next agent knows who claimed it.

One tool runs many models, and an agent reading someone else's unproven claim needs to know which one made it. godkit verify rejects a bare tool name.

Compatibility

Four tools, one protocol

Same 16 skills, same .agent/. Only the install path differs.

Tool Skills go to Rules file Protocol is
Claude Code ~/.claude/skills/ CLAUDE.md enforced by a hook
Codex ~/.agents/skills/ AGENTS.md enforced by a hook
Cursor no skill dir .cursor/rules/godkit.mdc instructed
Antigravity ~/.gemini/antigravity/ .agents/rules/godkit.md instructed

Enforced means the turn is blocked until the log exists. Instructed means the rule is in the tool's own rules file. All four are generated from one AGENTS.md and byte-compared in CI, so they cannot drift apart.

Reference

What you actually type

godkit init scaffold .agent/ + the rule files, and set up this machine once
godkit init --new a project with no code yet: a brief instead of a map
godkit sprint new "…" a goal, and waves of file-disjoint tasks under it
godkit sprint close refuses while anything in it is unfinished or unproven
godkit verify every task and log against the rules the templates state
godkit doctor what is set up, and whether the map went stale
