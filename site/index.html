Claims that hold

Subagents that obey their file, on any agent.

A named agent runs as its own codex exec or claude -p process. Read-only means a read-only sandbox, not a polite request.

Discover

Everything an agent needs, nothing it can break

  • Guard

    Denies force push, reset --hard, a download piped into a shell, writes to .env and .git/.

  • Subagents

    Explorer, planner, reviewer, implementer. Permissions from the file, enforced by the sandbox.

  • Checkpoints

    The tree is saved as a hidden git ref before each edit. godkit rewind goes back, and can be undone.

  • MCP server

    Nine tools on all four agents: claim, log, recall, map, verify, delegate, run a subagent.

  • Sprints

    Waves of tasks whose files cannot overlap, a join gate after each, and no close while anything is unproven.

  • Verify

    A "done" without the command and its output is a blocking finding. So is a log signed by a tool, not a model.

What you actually type

Usually one command. The agents run the rest themselves.

godkit init
the project and, once, the machine: .agent/, rules, skills, hooks, MCP
godkit doctor
what is set up, and which agents really ran it
godkit agent run <name>
a named subagent with enforced permissions
godkit rewind
back to a checkpoint taken before an edit
godkit sprint new "…"
a goal and its waves of file-disjoint tasks
godkit verify
is every "done" backed by evidence? Non-zero if not
